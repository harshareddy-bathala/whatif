
# whatif — a "what-if" risk-focused assistant

whatif is a small full-stack prototype: a chat app where the assistant deliberately answers from the risk / downsides perspective. Responses are polite and concrete and focus on likelihoods, failure modes, edge cases, and "what-if" scenarios, with optional mitigation suggestions so users can see the other side of the coin.

This repo pairs a Vite + React frontend with a Convex backend to run serverless functions and store conversation state during development.

## Purpose and core behaviour

- Intent: surface risks and downsides in a structured, non-alarmist way so users can make better-informed decisions.
- Response style: concise, polite, evidence-grounded where possible, presenting:
	- Likelihoods (qualitative or quantitative when supported)
	- Failure modes and edge cases
	- Concrete "what-if" scenarios and examples
	- Optional mitigations or next steps

Example assistant structure for any user prompt:
1. Short summary of the most relevant downside(s)
2. Likelihood / confidence (low / medium / high, or numeric when available)
3. Key failure modes and edge cases
4. Short examples / what-if scenarios
5. Practical mitigations (if applicable)

## Contract (inputs / outputs / error modes)

- Input: free-text user prompt (may include context like system state or data snippets)
- Output: short, structured risk-focused assistant reply as described above
- Error modes:
	- Missing context -> assistant asks for clarifying details
	- Model hallucination or uncertainty -> assistant marks confidence low and recommends verification
	- Sensitive content -> assistant flags ethical/privacy concerns and avoids unsafe guidance

## Quick start (local)

1. Install dependencies

```powershell
npm install
```

2. Configuration

Create a `.env` file in the project root (do not commit). Common variables:

```
OPENAI_API_KEY=sk-...

```

3. Run local development (frontend + Convex backend)

```powershell
npm run dev
```

This starts `vite` for the frontend and `convex dev` for the backend in parallel.

## OpenAI & data handling notes

- The assistant's responses are generated by a language model (OpenAI or similar). Configure your API key in `.env`.
- Safety first: the assistant is tuned to avoid providing instructions that enable harm. When a user requests dangerous or illegal actions, the assistant should refuse and explain the risks.
- Privacy: conversations may be stored in Convex during development. Treat any production deployment carefully — avoid logging PII, and add user consent flows where needed.

## Design trade-offs and edge cases

- Over-warning: the assistant might surface many low-likelihood failure modes; mitigate by adding a confidence indicator and a "short summary" at the top.
- False reassurance: avoid definitive statements when uncertain; prefer probabilistic language and cite assumptions.
- Context-sensitivity: risk assessment depends on user context. The assistant should request missing context before making high-confidence claims.
